One log, paid on every call.

An agent re-sends its whole context with each request. Whatever it reads early is billed again and again until the session ends or compacts.

55 later calls re-send it.

That one read costs as much as 6.75 fresh reads of the same text.

Bounded to 800 tokens with tail -n 40, it would cost 87% less.

Claude pricing ratios: cache write 1.25×, cache read 0.1× of fresh input.

The rules

A skill of about 850 tokens that changes what the agent asks for.

  1. Locate, then read. Check the size, grep, read the range.
  2. Compute, don't read. Data questions get a one-liner.
  3. Bound every command. Log to a file, tail it, grep it.
  4. Never re-read what is already in context.
  5. Batch independent calls in one turn.
  6. Diffs over files. git diff --stat first.
  7. Edit, don't rewrite.
  8. Narrow searches and fetches.
  9. Delegate wide exploration to a subagent.
  10. Answer lean. Result first, no recap.

Guardrails: never save tokens by hiding the real error, guessing a file, or skipping tests.

The audit

Reads your own Claude Code and Codex transcripts, prices every oversized read, noisy log and wasted round-trip, and names the rule that fixes it.

python3 tokenleak.py --since 30d

Local and read-only. No network, no telemetry, standard library only.

The plugin

In Claude Code the rules load at session start, after every compaction, and inside every subagent you spawn.

Ask it to audit your tokens: you also see what your CLAUDE.md and session-start context cost on every call.

Works with any agent that reads skills.

Measured, not promised.

Same prompt, a fresh copy of the same repo for every run, five runs per arm. The only difference is the rules in the system prompt. A script checks every result.

  • The rules were piloted first (30 runs, −23%). Two rules were added after reading those transcripts, so the feature task was written beforehand and never used for tuning.
  • One model and four small tasks on a synthetic repo built around what leaks in real ones. Your numbers will differ: run the audit before and after.
  • Every run, the exact rules used and the harness are in the repo.

Questions

Does it make the agent worse?

Not in the benchmark: 20 of 20 tasks passed in both arms, each checked by a script. The rules forbid saving tokens by guessing a file, hiding the error or skipping verification.

Isn't shorter output enough?

Output is the small part of the bill in agentic coding. Most of it is input context re-sent on every call. tokenleak works on what enters the context, and the audit shows the split on your own sessions.

How accurate is the audit?

Session totals and costs come straight from the transcripts. The size of each individual tool result is estimated at about four characters per token, and "avoidable" only counts what exceeds a sane budget, so it errs on the low side.

What about rtk, caveman and the rest?

They complement it. rtk compresses command output at the shell level and output-style skills shorten replies. tokenleak changes what the agent asks for and measures the result. Run the audit before and after anything you install.

Does anything leave my machine?

No. The audit reads files under ~/.claude/projects and ~/.codex/sessions and prints a report. It makes no network calls; the source is one readable Python file.
